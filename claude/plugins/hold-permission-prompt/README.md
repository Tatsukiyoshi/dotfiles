# hold-permission-prompt

Claude Code のツール確認ダイアログを出す代わりに、確認待ちの操作を保留にする Mod。保留中もユーザーは入力欄で普通に会話でき、会話のあとに承認・却下できる。承認・却下は、入力欄の上の帯のボタン（ターミナル・デスクトップアプリ）か、入力欄に打つ合言葉（Zed 等を含むすべてのクライアント）で行う。

## 背景

Claude Code では、ツールの許可を確認しているダイアログの表示中にメッセージを送ると、そのツール実行が「却下」扱いになる。確認とは関係のない話をしたいだけでも操作が却下され、同時に送信待ちだったツール呼び出しも止まる（dotfiles#8）。

許可ダイアログ自体は Mod から描き換え・フックできないため、ダイアログを出す前の判定（`tool.check`）で確認待ちになる操作を横取りし、Mod 側で保留する。

## 動き

### 確認待ちの操作（AskUserQuestion 以外）

1. `tool.check` で、エンジンの判定が `ask`（確認ダイアログを出す）になった操作を、通し番号（`#N`）を振って保留にする。モデルには `deny` と保留理由を返す。保留理由では、ユーザーに保留中の操作の内容と合言葉（`!ok N` / `!ng N`）を伝えること、承認されるまで同じ操作を再試行しないことを指示する
2. 入力欄の上の帯（`AbovePrompt`）に保留中の操作（番号・ツール名・対象）を並べ、「承認」「却下」ボタンを付ける
3. 保留中もユーザーは入力欄で普通に会話できる。却下扱いにはならない
4. 承認すると、その操作（ツール名と入力の組）を **1回分だけ** 承認済みとして記録し、再実行を依頼する。モデルが同じ操作を出し直すと、`tool.check` で確認なしに `allow` する。承認済みの記録は1回使うと消える
5. 却下すると、却下した旨をモデルに伝える
6. 帯のボタンで承認・却下した連絡は、ターンの実行中に押された場合は溜めておき、ターンが終わったとき（`turn.complete`）にまとめて1件の依頼として送る。ターンが動いていないときに押された場合はすぐ送る

エンジンの確認ダイアログは出さない（その表示中はまた割り込めなくなるため）。

#### 再実行の依頼に載せる入力

再実行の依頼には、保留した操作の入力（JSON）を「次の入力のまま再実行すること」として載せる。ただし JSON が 500 文字を超える場合（Write のファイル内容等）は載せず、「保留したときと同じ入力のまま再実行すること（入力は保留時の呼び出しを参照）」とだけ書く。ファイル内容が丸ごと会話に流れるのを避けるため。

### 合言葉

入力欄の上の帯はターミナルとデスクトップアプリでしか描画されず、Zed 等の SDK ホストでは表示されない。どのクライアントでも操作できるよう、入力欄に次の合言葉を打つと承認・却下できるようにする。

| 合言葉 | 動き |
| --- | --- |
| `!ok` | 一番新しい保留中の操作を承認する（質問は対象外） |
| `!ng` | 一番新しい保留（操作・質問）を却下する。質問なら取り下げる |
| `!ok N` / `!ng N`（`!ok 1 2` のように複数可） | 番号 `#N` の保留を承認・却下する |
| `!ok all` / `!ng all` | 保留中の操作をすべて承認・却下する（`!ng all` は質問も取り下げる） |

- 合言葉のプロンプトは `prompt.submit` で横取りし、そのプロンプト自体を承認・却下の連絡に書き換えてモデルに渡す（Mod から別のプロンプトを送らないため、SDK ホストでも確実に届く）。ターン中にボタンで溜めた連絡があれば一緒に載せる
- 該当する保留がない合言葉はモデルに渡さず落とす
- 合言葉として扱うのはユーザー自身の入力（ターミナル `composer`・SDK ホスト `sdk`・Remote Control `bridge`）だけ。通知や他のセッションからのメッセージは対象外
- ターミナルの帯のボタンは、入力欄にフォーカスがあると押せない。`ctrl+x` → `tab` で帯にフォーカスを移してから選ぶ（帯にもこの案内と合言葉を表示する）

### AskUserQuestion（ユーザーへの質問）

AskUserQuestion は `tool.check` の `ask` を通らず、hook の `allow` ではダイアログを閉じられない（ユーザーに質問するツールは hook が判定を厳しくする方向にしか変えられない）。そのため `tool.call` で横取りする。

1. `tool.call` で AskUserQuestion を受け取り、通し番号を振って保留にし、エンジンのダイアログを出さずに `deny` で返す。モデルには「質問を帯に表示した。帯を表示できないクライアントもあるため、質問と選択肢を番号付きで会話に書き出してから回答を待つこと」と伝える
2. 帯に質問文と選択肢ボタンを出す。単一選択の質問は選択肢を押すとその選択肢に決まり、複数選択の質問は選択肢を押すたびに ON/OFF が切り替わる
3. すべての質問に1つ以上の選択肢が選ばれると「回答を送信」ボタンが押せるようになり、押すと「質問『…』への回答: ○○」をまとめてモデルに送る（送信のタイミングは上の6と同じ）
4. 「取り下げ」ボタン・`!ng N` で、回答せずに保留から消せる（モデルには質問を取り下げた旨を送る）
5. 「その他」の自由回答や、帯が表示されないクライアントでの回答は、入力欄に普通に書く

#### 回答済みにするツール（`resolve_question`）

入力欄に普通に書いた回答は、Mod からは回答なのか雑談なのか判断できない。そのため、判断をモデルに任せる。

- Mod は `session.start` で、質問を回答済みにするツール `mcp__hold-permission-prompt__resolve_question`（引数: 通し番号 `no`・回答の要約 `answer`）を登録する
- 質問の保留理由で、「ユーザーの入力を読んで質問 #N への回答だと判断したら、このツールで回答済みにすること。回答でない入力（雑談等）のときは呼ばないこと」と指示する
- モデルがこのツールを呼ぶと、Mod はその質問を保留から消す（帯からも消える）。モデルへの連絡は送らない（回答はユーザーの入力としてすでにモデルに届いているため）
- このツール自体が保留されると質問がいつまでも残るため、`tool.check` ではこのツールだけ確認なしで通す

### 対象外（これまでどおりの動き）

- ExitPlanMode（プランの承認）: ユーザーの確認が必須のツールで、hook の `allow` ではダイアログを閉じられないため、これまでどおりエンジンのダイアログを出す
- `$.tool.check` による問い合わせ（実際の呼び出しではなく `tool_use_id` を持たないもの）: 保留にせず、エンジンの判定をそのまま返す

### 承認済みとして扱う範囲

同じツール名・同じ入力（入力を JSON 文字列にして完全一致）の呼び出し **1回分** に限る。安全性を今のダイアログ（その場の1回だけ許可）と揃えるため。

### 制限事項

- 権限モードを Mod から読む API がないため、`auto` モード（確認をモデルの分類器が判定するモード）でも `ask` になった操作は保留にする。`auto` モードでは使わない前提とする
- サブエージェント内の確認待ちも保留にする。サブエージェントは保留理由を受け取って終了するため、再実行の依頼はメインの会話に届き、メインのモデルが改めて実行する
- 保留中の操作・承認済みの記録はセッション内だけで保持する（`$.state`）。セッションをまたいでは残らない

## 配置

dotfiles の `claude/plugins/hold-permission-prompt/` で管理し、`setup-claude.sh` で `~/.claude/mods/hold-permission-prompt/` にコピーする。この README も一緒にコピーするため、新しい環境では Claude に「`~/.claude/mods/` の Mod を使えるようにして」と頼めば、配置先の README を読んで下記の設定を行える。`~/.claude/plugins/` は Claude Code がマーケットプレイスのプラグイン管理（キャッシュ・未使用分の掃除）に使うフォルダのため、自前の Mod は置かない。

読み込みは `CLAUDE_CODE_PLUGIN_DIRS` で行う。`~/.claude/settings.json` の `env` に次のように書く（`~` が使える。複数ある場合はプラットフォームのパス区切り文字でつなぐ。Windows は `;`、macOS・Linux は `:`）。Zed 等の SDK ホストから起動するセッションにも効く。

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "~/.claude/mods/hold-permission-prompt"
  }
}
```

1回だけ試す場合は `claude --plugin-dir ~/.claude/mods/hold-permission-prompt` で起動する。

Mod API は `tool.check` イベントを使うため、Claude Code 2.1.293 以降が必要。

- 動作確認済み: 2.1.293（Zed に同梱の SDK 0.3.293）、2.1.296（CLI）
- 動作しない: 2.1.247（`tool.check` イベントがなく読み込めない）
- 2.1.248〜2.1.292 は未確認
